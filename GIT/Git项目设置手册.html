第 0 章 · 阅读须知

Git 是什么、能解决什么问题

Git 是一个代码版本管理工具。它能帮你：

  • 记录代码每次修改，改坏了能回到任何历史版本
  • 多人协作不打架
  • 代码备份到云端，电脑坏了不丢
  • 查看"这段代码是谁、什么时候、为什么改的"

Git 与 GitHub / Gitee 的关系

概念是什么
Git装在你电脑上的工具，管代码版本
GitHub国外的代码托管平台（类似代码界的网盘），要科学上网
Gitee国内的代码托管平台（码云），访问快，中文界面
仓库（Repository）一个项目的所有代码 + 历史记录

Gitee（推荐）

  • ✅ 国内访问快，不用科学上网
  • ✅ 中文界面
  • ✅ 免费私有仓库
  • ⚠️ 国际影响力小

GitHub

  • ✅ 全球最大开源平台
  • ✅ 生态最丰富
  • ⚠️ 国内访问慢，需科学上网
  • ⚠️ 私有仓库要付费（学生包免费）
本手册主推 Gitee，第 3.3 节附带 GitHub 方案，两者步骤几乎一样。

本次目标

把 G:\【0】209 Python\【ORYXOS】\GIT\ 这个目录变成一个 Git 仓库，并把代码推送到 Gitee。

关键术语速查

术语意思
仓库（repo）一个项目的代码 + 历史记录
提交（commit）保存一次修改，给这次修改起个名字（"修了登录 bug"）
推送（push）把本地提交上传到远程（Gitee/GitHub）
拉取（pull）把远程的新修改下载到本地
分支（branch）代码的"平行宇宙"，不同分支可以独立开发
合并（merge）把一个分支的修改合到另一个分支
主分支代码的"主线"，名字通常是 main 或 master

第 1 章 · 安装 Git

好消息：你的电脑已经装了 Git（git version 2.55.0）。本章可以跳过，直接看第 2 章。

如果以后换电脑或重装系统，按下面步骤装：

步骤 1：下载 Git

  1. 打开 https://git-scm.com/download/win
  2. 会自动开始下载（Git-2.x.x-64-bit.exe）
  3. 下载慢的话用国内镜像：https://npmmirror.com/mirrors/git-for-windows/

步骤 2：安装

  1. 双击安装包
  2. 一路 Next（所有选项保持默认就行）
  3. 最后点 Install → Finish
安装过程中会问几个选项，全部默认即可：
• 默认编辑器（默认 Vim，新手可以改成 VS Code）
• 默认分支名（默认 main，OK）
• PATH 环境（默认）
• 行尾符转换（默认）

步骤 3：验证安装

  1. 按 Win + R，输入 cmd 回车
  2. 输入：git --version
  3. 显示 git version 2.x.x = 成功

第 2 章 · 配置 Git（首次必做）

第一次用 Git 要告诉它"你是谁"，不然 commit 报错。

步骤 1：打开命令行

  1. 按 Win + R，输入 cmd 回车
  2. 或者右键桌面 → 在终端中打开

步骤 2：设置用户名

在命令行里输入（把"你的名字"改成你的真实姓名或昵称）：

命令提示符
C:\Users\Administrator> git config --global user.name "你的名字" # 例如：git config --global user.name "Zhang San" # 这个名字会显示在每次 commit 上

输入完回车，没报错就是成功了。

步骤 3：设置邮箱

这个邮箱一定要和 Gitee/GitHub 注册邮箱一致，否则头像和贡献不显示。

命令提示符
C:\Users\Administrator> git config --global user.email "your-email@example.com" # 例如：git config --global user.email "zhangsan@163.com"

步骤 4：设置默认分支名为 main

命令提示符
C:\Users\Administrator> git config --global init.defaultBranch main # 2020 年后 GitHub/Gitee 默认都用 main，不用 master

步骤 5：设置行尾符（Windows 必加）

命令提示符
C:\Users\Administrator> git config --global core.autocrlf true # Windows 提交时把 LF 转成 CRLF，拉取时再转回来 # 不设这个会导致 Python 文件每次 diff 都显示"全部改了"

步骤 6：验证配置

命令提示符
C:\Users\Administrator> git config --list user.name=你的名字 user.email=your-email@example.com init.defaultbranch=main core.autocrlf=true # 应该能看到上面这几个配置项
配置完成标志：看到 user.name 和 user.email 就 OK 了。

  3. 仓库介绍：可选，填 ORYXOS Python 项目
  4. 是否开源：选 私有（只有你能看到）
  5. 初始化：
    • ❌ 不要勾选"使用 Readme 文件初始化这个仓库"

本地已经有目录了，不要让 Gitee 自动生成文件，否则会冲突。
📍 创建仓库页面（关键选项位置） • 仓库名称：输入框
• 是否开源：单选按钮（选私有）
• 初始化选项：三个复选框，全部取消勾选

步骤 3：记下仓库地址

创建后跳转到仓库页面，地址栏显示：

https://gitee.com/你的用户名/oryxos.git
把 你的用户名 替换成你的 Gitee 用户名。
这个地址后面要用，先复制下来（右键 URL 复制）。

第 4 章 · 配置 SSH 密钥

为什么用 SSH 而不是 HTTPS

HTTPSSSH
每次 push 要输密码是（且 GitHub 已不支持密码，要 PAT）❌ 不用
配置复杂度简单中等
安全性中等高
推荐临时用长期使用推荐

4.1 生成 SSH 密钥

步骤 1：在命令行生成密钥

按 Win + R → cmd 回车，输入：

命令提示符
C:\Users\Administrator> ssh-keygen -t ed25519 -C "your-email@example.com" # 把邮箱换成你 Gitee 注册的那个邮箱 Generating public/private ed25519 key pair. Enter file in which to save the key (C:\Users\Administrator\.ssh\id_ed25519): # 这一步直接回车，用默认路径 Enter passphrase (empty for no passphrase): # 这一步输入一个密码（或直接回车留空） # 如果留空，push 时不用输密码（推荐） Enter same passphrase again: # 再输一次密码（或回车） Your identification has been saved in C:\Users\Administrator\.ssh\id_ed25519. Your public key has been saved in C:\Users\Administrator\.ssh\id_ed25519.pub. # 看到这两行就成功了
建议：第一次可以留空（直接回车两次），省去每次 push 输密码的麻烦。
等你熟了再回来设密码保护。

4.2 查看并复制公钥

步骤 1：显示公钥

命令提示符
C:\Users\Administrator> type C:\Users\Administrator\.ssh\id_ed25519.pub ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIxxxxxxxxxxxxxxxxxxxxxxxxxxx your-email@example.com

会显示一串以 ssh-ed25519 开头的长字符串，全选复制（从 ssh-ed25519 到邮箱，整行）。

4.3 把公钥配到 Gitee

步骤 1：进入 SSH 公钥设置

  1. 登录 Gitee
  2. 右上角头像 → 设置
  3. 左侧菜单 SSH 公钥

步骤 2：添加公钥

  1. 点 添加公钥
  2. 标题：填 我的 Windows 电脑（随便起，自己认得出来）
  3. 公钥：粘贴刚才复制的字符串
  4. 点 确定
📍 设置 → SSH 公钥 一个大文本框，把刚才复制的 ssh-ed25519 字符串粘贴进去

4.4 测试连接

步骤 1：测试 SSH 连接

命令提示符
C:\Users\Administrator> ssh -T git@gitee.com The authenticity of host 'gitee.com (xxx.xxx.xxx.xxx)' can't be established. ED25519 key fingerprint is SHA256:xxxxxxxxxxxx. Are you sure you want to continue connecting (yes/no)? # 输入 yes 回车 Hi 你的用户名! You've successfully authenticated, but GITEE.COM does not provide shell access. # 看到 "Hi 你的用户名!" 就说明配置成功
SSH 配置完成标志：看到 Hi 你的用户名!
看到 Permission denied (publickey) 说明公钥没配对，回去第 4.3 节检查。

第 5 章 · 初始化本地仓库并推送

5.1 关键路径确认

你的项目目录是：

G:\【0】209 Python\【ORYXOS】\GIT\

路径里有：

  • 中文：【0】209 Python、ORYXOS
  • 数字：0、209
  • 空格：【0】209 Python 中间有空格
  • 方括号：【】
路径里包含中文、方括号、空格的注意事项（详见第 9 章）：
  • Git 支持这些字符，但偶尔会出现引号/转义问题
  • 命令行 cd 这种路径时必须用英文双引号包起来
  • 建议路径里别有空格（有的话要引号）
  • 如果后面遇到奇怪的报错，第一反应：检查路径引号

5.3 创建 Python 项目的 .gitignore

在做任何 git 命令之前，先创建 .gitignore，避免把虚拟环境、缓存文件 commit 上去。

步骤 1：在项目目录里新建 .gitignore 文件

  1. 在文件资源管理器打开 G:\【0】209 Python\【ORYXOS】\GIT
  2. 右键 → 新建文本文档
  3. 改名为 .gitignore（注意没有 .txt 后缀）
Windows 默认不显示文件扩展名。改成 .gitignore.（末尾加点）可以强制建立无扩展名文件。
或者用记事本另存为 → 文件类型选"所有文件" → 填 .gitignore。

步骤 2：用记事本打开 .gitignore

  1. 右键 .gitignore → 打开方式 → 记事本
  2. 复制下面这些内容粘贴进去：

这些被忽略的文件是干嘛的：

第 6 章 · 日常使用

6.1 修改文件后提交

这是你以后每天都会做的循环：

日常工作流
# 1. 改了文件后，查看修改了哪些 G:\【0】209 Python\【ORYXOS】\GIT> git status # 2. 看具体改了啥 G:\【0】209 Python\【ORYXOS】\GIT> git diff # 3. 暂存（add） G:\【0】209 Python\【ORYXOS】\GIT> git add . # 或者只 add 某个文件：git add main.py # 4. 提交（commit） G:\【0】209 Python\【ORYXOS】\GIT> git commit -m "修复了某某 bug" # 5. 推送到远程（Gitee） G:\【0】209 Python\【ORYXOS】\GIT> git push
git add / commit / push 三步走的意义：
• add：把修改放进"待提交"区
• commit：确认提交，生成一个历史版本
• push：把本地历史同步到远程

类比：add = 把信放进信封，commit = 封口贴邮票，push = 投递

6.4 撤销修改

场景命令
撤销还没 add 的文件修改git checkout -- 文件名
撤销已经 add 但还没 commitgit reset HEAD 文件名
撤销已经 commit（保留修改）git reset --soft HEAD~1
撤销已经 commit（删除修改）git reset --hard HEAD~1
git reset --hard 危险！
会彻底删除你的修改，且无法恢复。
除非你 100% 确定要这么做，不要用 --hard。

第 7 章 · 分支管理

什么是分支

分支可以理解为代码的"平行宇宙"。

  • main 是稳定版本，永远保证能跑
  • 开发新功能时，开个 dev-新功能 分支
  • 新功能测试好了，再合并回 main

常用分支命令

分支操作
# 查看所有分支（当前分支前有 *） G:\【0】209 Python\【ORYXOS】\GIT> git branch # 创建新分支 G:\【0】209 Python\【ORYXOS】\GIT> git branch dev # 切换到新分支 G:\【0】209 Python\【ORYXOS】\GIT> git checkout dev # 或者一条命令搞定：git checkout -b dev （创建并切换） # 在 dev 分支上改完代码、add、commit 后，切换回 main G:\【0】209 Python\【ORYXOS】\GIT> git checkout main # 把 dev 合并到 main G:\【0】209 Python\【ORYXOS】\GIT> git merge dev # 删除 dev 分支（合并完就可以删了） G:\【0】209 Python\【ORYXOS】\GIT> git branch -d dev
新手建议：个人项目初期可以只用 main 一个分支。多人协作或做大的功能改动再开分支。

第 8 章 · .gitignore 配置

必须忽略的 Python 文件

第 5.3 节已经给了完整模板，这里再强调几个最容易被小白踩坑的：

路径必须忽略原因
.venv/✅ 必虚拟环境，几百 MB，且能根据 requirements.txt 重建
__pycache__/✅ 必Python 自动生成，每个 .py 文件都会配一个目录
*.pyc✅ 必编译过的 Python 文件
.env✅ 必API 密钥、数据库密码，绝对不能 commit
*.db / *.sqlite✅ 建议本地数据库文件
*.log✅ 建议日志文件
.vscode/⚠️ 看情况VSCode 配置，团队项目一般忽略

.gitignore 不生效怎么办

如果某个文件已经被 commit 过，再加 .gitignore 也无法忽略它。需要先从 Git 缓存里移除：

清理已跟踪文件
# 从 Git 缓存移除（保留本地文件） G:\【0】209 Python\【ORYXOS】\GIT> git rm --cached .env # 然后正常提交 G:\【0】209 Python\【ORYXOS】\GIT> git commit -m "把 .env 加入 .gitignore" G:\【0】209 Python\【ORYXOS】\GIT> git push
如果 .env 已经 push 到公开仓库：
立即修改密钥（API key、数据库密码），因为别人已经看到了。
然后按上面步骤从仓库移除。改密钥这一步不能省！

第 9 章 · 中文路径与方括号的处理

你的项目路径包含：

  • 中文：【0】209 Python、ORYXOS
  • 空格：【0】209 Python 中间有空格
  • 方括号【】

Git 完全支持这些字符，但有几个坑：

9.1 cd 路径要用双引号

cd 路径
C:\Users\Administrator> cd /d "G:\【0】209 Python\【ORYXOS】\GIT" # ✓ 正确：双引号包住整个路径 C:\Users\Administrator> cd /d G:\【0】209 Python\【ORYXOS】\GIT 系统找不到指定的路径。 # ✗ 错误：没引号，空格导致路径被截断

9.2 git 命令里的路径

git 命令后面跟路径时，如果路径含空格或中文，也要用双引号：

git 命令路径
G:\【0】209 Python\【ORYXOS】\GIT> git add "G:\【0】209 Python\【ORYXOS】\GIT\main.py" # 如果路径里有空格或中文，git add 后面的路径要引号 # 不过用 git add . 就没这个问题（. 表示当前目录）

9.3 方括号【】的处理

Windows 文件名 允许 使用 【】（这些是中日韩标点，不是英文方括号 []）。Git 也支持。

但有些 Git 操作（比如 git log -- 文件路径）里，如果路径包含特殊字符，可能需要转义。日常使用基本遇不到，遇到再说。

9.4 强烈建议

虽然 Git 支持中文路径，但建议：
1. 路径里不要有空格（用下划线或连字符代替）
2. 路径里尽量用英文，中文项目名用拼音
3. 不要有方括号【】

例如你的项目可以改成 G:\python-projects\oryxos\，省去 90% 的路径问题。

但既然你已经有这个目录了，也能用，按手册的引号写法操作即可。

第 10 章 · 常见问题

Q1: 提示 "Please tell me who you are"

原因：没配 user.name / user.email

解决：回第 2 章步骤 2、3

Q2: 提示 "Permission denied (publickey)"

原因：SSH 公钥没配到 Gitee，或者配错了

解决：

  1. 回第 4.2 节重新复制公钥
  2. 回第 4.3 节重新粘贴
  3. 回第 4.4 节重新测试

Q3: HTTPS 协议 push 失败（密码错误）

原因：2021 年后 GitHub/Gitee 不再支持密码 push，需要 PAT（Personal Access Token）

解决（推荐切换 SSH）：用第 4 章的 SSH 方案，免密码。

Q4: push 时提示 "Updates were rejected"

原因：远程有本地没有的提交（别人 push 过，或你在另一台电脑 push 过）

解决：

先 pull 再 push
G:\【0】209 Python\【ORYXOS】\GIT> git pull origin main # 先拉取远程的更新，可能会有冲突（冲突就手动解决） G:\【0】209 Python\【ORYXOS】\GIT> git push origin main # 再推送

Q5: 误把 .env 或密钥 commit 上去了

立刻做三件事：

  1. 改密钥（API key、数据库密码）—— 这是最关键的
  2. 从仓库移除（见第 8.3 节）
  3. 通知团队成员密钥已泄露

Q6: 改了 .gitignore 但文件还是被跟踪

用 git rm --cached <文件> 解除跟踪（详见第 8 节）。

Q7: 出现 "filename too long" 错误

原因：Windows 路径长度限制（260 字符）

解决：

  1. 把项目移到更浅的目录（比如直接放 D:\oryxos\）
  2. 或者用 git 命令行：git config --system core.longpaths true（需要管理员权限）

Q8: 主分支是 master 不是 main

解决：

改名 master → main
G:\【0】209 Python\【ORYXOS】\GIT> git branch -M main # 把当前分支改名为 main G:\【0】209 Python\【ORYXOS】\GIT> git push -u origin main

Q9: commit 后想改 commit message

最近一次 commit 改 message：

改 commit message
G:\【0】209 Python\【ORYXOS】\GIT> git commit --amend -m "新的 commit message"

Q10: 在另一台电脑 clone 这个仓库

克隆仓库
D:\> git clone git@gitee.com:你的用户名/oryxos.git # 把仓库克隆到当前目录 # 会创建一个 oryxos 子目录，里面是完整的代码 + 历史
